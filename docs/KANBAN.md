## How to move cards

1. Check actual deliverables and link reviewed PR, passing relevant tests, submitted coursework or recorded team decision.
2. On the GitHub Issue, **replace** one `stage:` label (do not leave two). Status in this Markdown is a snapshot only.
3. Only close **implementation** issues after integration, security, acceptance and production-relevant tests; a UI prototype is not a real data/auth/AI service.
4. Use branches/PRs with documented reviewers and per-team owner confirmation. The read-only HTML dashboard is **not** a draggable Projects board.
