## How to maintain this work board

1. Open an issue and remove its former **stage:** label before applying the new one (one stage per issue).
2. Update the acceptance checklist and paste references to decisions, tests and pull requests.
3. Close an issue only when its own artifact is genuinely complete. A written assignment never proves implemented functionality.
4. Use the [read-only interactive board](../board/README.md) for live stages; this Markdown view remains an October 28 snapshot unless manually refreshed.
5. If the team wants a *native* drag-and-drop GitHub Project, create a **Board** project in GitHub and import these Issues, with seven Status options matching the labels. This integration cannot create that native Project automatically.
