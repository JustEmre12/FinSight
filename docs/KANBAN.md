## Board stage filters

- **[Product Backlog (12)](https://github.com/JustEmre12/FinSight/issues?q=label%3A%22stage%3Abacklog%22)** — Approved idea/feature but not selected as ready; implementation not verified.
- **[Ready (12)](https://github.com/JustEmre12/FinSight/issues?q=label%3A%22stage%3Aready%22)** — Defined work candidates; implementation has not been started or proved.
- **[In Progress (4)](https://github.com/JustEmre12/FinSight/issues?q=label%3A%22stage%3Ain-progress%22)** — Provisional planning lane; owner must confirm active status.
- **[In Review (7)](https://github.com/JustEmre12/FinSight/issues?q=label%3A%22stage%3Ain-review%22)** — Documentation exists, but team/instructor sign-off is pending.
- **[Done (21)](https://github.com/JustEmre12/FinSight/issues?q=label%3A%22stage%3Adone%22)** — Completed written/modeling deliverables only; no website code confirmed.
- **[Blocked (5)](https://github.com/JustEmre12/FinSight/issues?q=label%3A%22stage%3Ablocked%22)** — Waiting for a decision, data-provider feasibility or collaborator access.
- **[Future (7)](https://github.com/JustEmre12/FinSight/issues?q=label%3A%22stage%3Afuture%22)** — Ideas beyond the current core stock-research MVP.

## How to move cards
1. Open the linked Issue, update evidence/checklists, and **replace** its existing `stage:` label with the new stage.
2. For a documentation Issue, mark Done when the artifact exists and review requirements are met.
3. For an implementation Issue, mark Done **only after working functionality, reviewed PR, tests and documented acceptance**.
4. Leave source licensing, service selection, private data access and management approval blocked until confirmed.
5. The [interactive board webpage](../board/index.html) displays issue labels from GitHub when served; it is read-only. To create a native drag-and-drop GitHub Project, the owner must create a Project in GitHub and add these Issues—this connection does not expose that action.
